# Prototype feature coverage

| Module | Implemented prototype behaviour | Verification / limits |
|---|---|---|
| M1 Conversation | Paste, discovery brief, fixture, audio validation/upload progress, Batch job recovery, explicit short REST mode, microphone recording, global/per-turn speaker correction, exact turn splitting with lineage, search, originals, delete | REST verified with actual Prisma v3.0. Valid two-voice Batch job is queued; diarization/timestamp quality pending |
| M2 Intelligence | Local structured needs/signals, custom criteria/questions, exact quotes, explicit/inferred states, correction/dismissal, separate source/evidence checks, inferred coverage candidates | Small-model interpretations can be wrong. Confidence is uncalibrated; blind multilingual evaluation remains |
| M3 Sales | Catalogue-based fit/gaps, sources, unknown/escalation, questions/objections, discovery without recording, editable/copy pitch, language/audience controls | Pricing is intentionally undocumented. Retrieval has limited keyword coverage; technical checklists retain source English |
| M4 Academy | Six scenarios across two products, three turns, persisted history/reopen, knowledge Q&A, eight-category rubric, quotes and contextual alternatives | Scripted customers, baseline scores and optional real model coaching are labelled; not employee-performance assessment |
| M5 Requirements | Source-linked structured records, unknown custom scope, proposed criteria, constraints, questions, stories, merge/split | Proposed criteria require PM/engineering review; general generation is not independently validated |
| M6 PM | Triage, wording/stories/criteria/priorities/status edits, theme groups, same-capability overlap hints, confirmation/reasons, lineage, export | Confirmation is a human demo-role attestation; there is no external customer-signature integration |
| M7 Engineering | Four feasibility states, source lookup, conservative source-entailment bounds, dependencies/risks/questions, rationale editor, approve/reject | Model support checks fail closed to unknown; new documented scope requires a new approved source |
| M8 Integrity | Rules and model comparison, validated source/target quotes, candidate origins, original evidence, corrections, dispositions, stale-audit invalidation, final-response gate | 4B audit false positives were observed. Results are review candidates, not proof of full intent preservation |
| M9 Customer return | Short/detailed explanations, source templates, optional plain-language AI drafting and translation, exact approval, actual Timbre WAV and playback | Timbre verified. Independent bilingual listening/translation review remains; semantic audit is required before model-enabled approval |
| M10 Insights | Stored sample/language counts, expressed-wording evidence, authored controlled comparison, measured energy/silence and transcript-token pace per recording | Authored outcomes are fixtures, not measured causal effects. No pitch/emotion/employee scoring |
| Knowledge | Approved synthetic corpus plus persisted source drafts, Technical Reviewer approval, custom capability extension | Immutable first versions; no production source-revision/retention workflow |
| Evaluation | Unit/integration regressions, frontend build, isolated browser checks, real-call reports, 15-case coarse local evaluation and actual single-model summary | Authored data is not blind validation. Model audit precision/recall and independent audio metrics remain |
| Operation | Backend-only keys, local persistence, bounded provider requests, retry/resume, provider call provenance, version checks and runbook | Local demo roles are not production authentication; no public deployment or distributed worker claim |

Submission, portal details, video and public posting are deferred until prototype review, as requested. Live telephony, CRM/ERP production connectors, automatic tickets, billing/SSO and local 30B inference are outside this prototype.
